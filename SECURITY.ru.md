## Сообщение об уязвимости

Мы серьёзно относимся к безопасности **Tokio**. Если вы обнаружили уязвимость, **не публикуйте** её в открытых GitHub Issues, Pull Requests или обсуждениях.

### Порядок приватного раскрытия

1. Откройте **Private Vulnerability Report** на странице [GitHub Security Advisories](https://github.com/ValDagon/tokio/security/advisories).
2. Приложите подробное описание для воспроизведения и оценки:
   - Тип проблемы (утечка секретов, обход аутентификации, IDOR/нарушение изоляции пользователей, prompt injection, XSS, SQL-инъекция и т. д.).
   - Затронутый компонент (`src/handlers/`, `src/endpoints/rpc.ts`, `src/lib/dal/`, `miniapp/`, `scripts/` или инструменты сборки).
   - Минимальные шаги воспроизведения или Proof-of-Concept (PoC).
   - Потенциальное влияние при эксплуатации.

### Сроки реакции

- **Первичное подтверждение**: в течение 48 часов.
- **Оценка и триаж**: в течение 5 рабочих дней.
- **Исправление и публикация**: патч готовится приватно и выкатывается в `main`, с указанием автора отчёта по его желанию.

## Архитектура безопасности

- **Шифрование BYOK-ключей (`src/lib/crypto.ts`)**: пользовательские ключи Gemini API шифруются на pure-TypeScript реализации RFC 8439 ChaCha20-Poly1305 с уникальным 96-битным nonce и проверкой целостности HMAC-SHA256.
- **Аутентификация Mini App (`src/endpoints/rpc.ts`, `src/lib/auth.ts`)**: в production-режиме RPC-шлюз проверяет подпись Telegram WebApp `initData` (`HMAC-SHA256`) и актуальность `auth_date`.
- **Изоляция данных (`src/lib/dal/`)**: все пользовательские запросы в DAL фильтруются по `user_id` / `telegram_id`, с поддержкой открытого режима или закрытого белого списка (`ADMIN_IDS`, `BETA_WHITELIST`).
- **Трёхслойная защита от утечек**: приватный каталог `overlay/`, файлы секретов и `.forbidden-strings.local` исключены через `.gitignore`, проверяются локально хуком `.githooks/pre-push` (`scripts/check-leaks.mjs` + `gitleaks`) и принудительно контролируются в GitHub Actions CI.
